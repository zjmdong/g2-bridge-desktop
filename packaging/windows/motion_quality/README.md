# Offline motion-quality and texture-ownership research

These optional Windows diagnostics use **NVIDIA NVENC**, fixed 1920×1080,
100 fps media timestamps and a 20 Mbps CBR target. They never capture a desktop,
change displays or open USB. Run one GPU job at a time, separately from live
latency measurements. They are not imported by the desktop app.

Use the repository's Python environment and pinned FFmpeg build. NumPy is an
optional **research** dependency, not a new application dependency. The recorded
research used NumPy 2.4.6; install it into the research environment if needed:

```powershell
.venv/Scripts/python.exe -m pip install numpy==2.4.6
```

## Selected policy and frozen commands

`baseline-command-v024.json` preserves the original Baseline/qres command.
`candidate-high-only-v025.json` preserves the intermediate High/CABAC-only
candidate. `candidate-command-v025.json` is the final candidate: it additionally
sets both `-qp_cb_offset` and `-qp_cr_offset` to `-4`. All retain qres, P4, the
400,000-bit VBV, one reference, no B frames or lookahead, and the existing startup
IDRs. Spatial and temporal AQ remain off. Templates never silently import future
application defaults; a CPU test compares the final template's option semantics
with the current production command and rejects duplicate flags.

The selected 0.2.5 policy is **High/CABAC, qres, Cb/Cr QP offsets -4, AQ disabled**.
The chroma offsets were added after the intermediate High-only policy exceeded
the existing colour-edge pixel tolerance. They reduce chroma quantization; they
do not change BT.709 conversion, colour range or the target bitrate. Final-candidate
motion/colour measurements must be reported separately from the earlier High-only
results. Full-resolution
multipass improved some average motion/fine-texture scores but produced worse
scene-cut error spikes in the measured sequence, so it was not adopted. High's
host decoding results are not a new goggles optical or firmware-acceptance test.
Detailed comparisons belong in the release validation record.

## Picture quality

The default 540-frame source contains 300 frames of slow coherent movement,
then 60 frames each of fast 48-pixel/frame translation, repeated scene cuts,
moving fine texture, and deterministic new texture on every frame. The last
segment is intentionally adversarial and must not be the sole quality criterion.
Eight spatial frame-ID regions detect mismatched picture regions. Pixel truth
is regenerated by index rather than stored as a large raw video file.

CPU-only tests create tiny generated arrays and mocked processes; no FFmpeg,
GPU, desktop or device is opened:

```powershell
.venv/Scripts/python.exe packaging/windows/motion_quality/test_motion_quality.py
.venv/Scripts/python.exe packaging/windows/motion_quality/mailbox_texture_stress.py --self-test
```

Run the same generated source through the baseline and candidate, sequentially:

```powershell
.venv/Scripts/python.exe packaging/windows/motion_quality/check_motion_quality.py --path gpu-upload --profile baseline --output work/motion-baseline.json
.venv/Scripts/python.exe packaging/windows/motion_quality/check_motion_quality.py --path gpu-upload --template packaging/windows/motion_quality/candidate-command-v025.json --profile high --output work/motion-high.json
```

The quality tool's default profile remains Baseline for historical comparisons;
**supply `--profile high` with the candidate template**. An explicit CABAC template
combined with Baseline is rejected rather than silently running a different case.
For experimental fullres/AQ comparisons, keep the same source and change exactly
the intended option. Those options do not change the selected production policy.

`--path cpu-nv12` supplies canonical generated NV12 directly to NVENC.
`--path gpu-upload` converts the deterministic source to RGB, uploads it and uses
the production D3D11 conversion. Both paths use the hardware encoder. Add
`--gpu-raw-check` to inspect a separate conversion/readback pass without NVENC.
The RGB round trip can differ slightly through rounding and chroma sampling.
These finite quality runs disable the latest mailbox so every input has an
expected corresponding output. **Neither quality path exercises DDA ownership,
live display phase or headset presentation.**

Reports contain per-frame Y/U/V error, PSNR, 16×16 block-error distributions,
residual jumps across block boundaries, access-unit sizes, coded bitrates,
SPS/PPS and slice initial QP. Initial slice QP is not average picture QP or
macroblock AQ. PSNR `null` denotes exact identity. For sequence PSNR, aggregate
MSE first; averaging per-frame dB can hide severe scene-cut spikes. A fixed
20 Mbps target does not imply identical actual coded bytes between candidates.

Every access unit is decoded, with strict decoder-error and picture-count
checks. A second decode from the final IDR must match that suffix's continuous
decoded hashes. Reference-picture frame numbers and the SDK's 56,000-byte guard
are checked separately from quality; there is no invented perceptual pass score.
`--save-generated-h264` optionally retains only the generated clip. By default,
quality runs save numeric JSON, not pictures. Choose fresh output paths.

## Latest-mailbox texture stress

This separate test preserves real GPU upload/conversion, the latest-frame
mailbox and asynchronous NVENC. Seventeen independently salted frame-ID/CRC
markers are part of the same texture as the generated moving background.
The producer is not paced; a deliberately slow AVI reader creates test-only
backpressure. Normal stream latency cannot be inferred from this pressure run.

```powershell
.venv/Scripts/python.exe packaging/windows/motion_quality/mailbox_texture_stress.py --run --template packaging/windows/motion_quality/candidate-command-v025.json --output work/motion-mailbox-high.json
```

Default coverage requires at least 100 actual native raw-frame replacements
and 30 decoded pictures. Replaced raw IDs may be skipped, but submitted minus
decoded frames must equal the native replacement counter, and the final input
must drain. Access-unit counts, reference sequence and decoded picture order
must agree. Conflicting CRC-valid markers are classified as mixed; damaged or
low-confidence markers are inconclusive rather than proof of a texture race.
Whole-plane error is additional evidence, not a universal ownership proof.

Stress runs save generated H.264 plus numeric JSON and encoder/decoder/header
logs beside the requested output. They do not contain user desktop images.
Keep these generated artifacts under `work/`; public evidence should summarize
the measurements and replace machine-specific paths. No diagnostic binary or
per-frame research work enters the installed streaming path.

## Historical source provenance

The original measurements used the work-directory scripts recorded in
`provenance.json`. The published tools are reusable copies with different file
hashes: the repository-root lookup was relocated; quality failure cleanup now
joins its writer; a conflicting Baseline/CABAC command is rejected; and small
CPU tests cover these changes and the candidate templates. The original `work/`
scripts were not modified. Earlier `gpu-high.json` results used the baseline
template with a profile override; they are not the final chroma-offset results.
The final run's template hash is recorded separately in `provenance.json`.
That measured template used CRLF; the public final template uses LF with the
same parsed command. Both hashes are recorded. Converting only its LF line
endings back to CRLF reproduces the measured template bytes; no encoding option
changes are required.
Do not label the published tool hash as the hash used for older measurements,
or claim that a later rerun must produce byte-identical NVENC output.

`restore-measured-tools.patch` reverses only those code/test changes. To inspect
or rerun the original source, copy the three Python files and the baseline JSON
into a **new** `work/motion-measured/` directory, then run from the repository root:

```powershell
git -c core.autocrlf=false -c core.eol=lf apply --check --directory=work/motion-measured packaging/windows/motion_quality/restore-measured-tools.patch
git -c core.autocrlf=false -c core.eol=lf apply --directory=work/motion-measured packaging/windows/motion_quality/restore-measured-tools.patch
```

Check restored files against the original SHA256 entries in `provenance.json`.
The per-command settings preserve the recorded LF bytes on Windows without
changing the user's global Git configuration.
The original root lookup is correct only at that two-level work-directory
location. Restoring source does not itself execute a GPU test. The recorded
quality-script hash was `94b9ce8cad5e520d39beb7a48ce9724d00e6920350c17506f9d486fce81d438a`.
