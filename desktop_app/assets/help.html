第一次使用

  1. 准备 Windows x64 电脑、支持 H.264 NVENC 的 NVIDIA 显卡及驱动和 USB 数据线。本版仅使用 NVIDIA 硬件编码；编码不可用时会提示修复，不会自动切换到软件编码。
  2. 在「设备与驱动」检查环境。缺少驱动时点击「下载并安装驱动」，或选择本地 DJI Assistant 2 消费机系列 2.1.42 安装包。安装需要 Windows 管理员授权。
  3. 将眼镜开机，用支持数据传输的 USB 线连接电脑。建议使用 USB-A 转 USB-C 数据线；仅有 USB-C 接口时可增加合适的 USB-A 转接器。
  4. 在眼镜中进入「更多 → DJI Virtual Flight」。电脑无法替你完成这个菜单操作。
  5. 等待型号、固件检测完成。默认开启「插入 USB 后自动串流」；也可关闭该选项，选择参数后手动开始。在眼镜中确认画面。
  6. 点击「停止串流」或拔出 USB 均会结束串流、收回串流扩展屏。手动停止后不会立刻自动重启；下次重新插线会再次自动开始。可选择电脑主屏或独立扩展屏。

使用官方工具更新或恢复

  1. 停止串流并退出本客户端，避免和 DJI Assistant 同时占用 USB。
  2. 从 DJI 官方下载页面安装 DJI Assistant 2（消费机系列）。驱动安装与固件更新是两件不同的事。
  3. 保持设备电量充足、供电和 USB 连接稳定。打开 DJI Assistant，按官方界面要求登录并选择眼镜。
  4. 查看设备可用的固件列表，选择与型号匹配的已验证版本。只有官方界面提供降级时才可按该流程降级；若列表没有目标版本，不要尝试其他型号固件，应联系 DJI 支持。
  5. 按官方工具提示完成升级或刷新，过程中不要断电或拔线。
  6. 关闭 DJI Assistant，重新启动眼镜和本客户端，再次检测型号与固件。

常见问题

找不到眼镜

检查电源、数据线与 USB 端口，关闭可能占用设备的 DJI Assistant。客户端在后台监听 USB 插拔；手动「重新检测」可重试设备信息读取。插着多个受支持设备时请先只保留一台。

设备连接了，但一直等待

确认眼镜已进入 DJI Virtual Flight。USB 连接成功与视频握手成功是不同状态。若提示 d6 或无法退出 Virtual Flight，先停止串流，退出并重新进入该模式；必要时重启眼镜。

黑屏、画面冻结或反复重启编码

先停止串流，降低码率，重启眼镜后再试。SDK 会阻止超过其单帧预算的视频数据。切勿关闭限制或强制使用未验证固件。若设备无法正常启动，请使用官方恢复流程。

编码或桌面采集失败

确认电脑为 Windows x64，安装 NVIDIA 官方驱动并保持桌面解锁。本版使用无黄色采集边框的 Desktop Duplication 和 NVENC 硬件编码。P1 为速度优先，P4 为画质优先；游戏负载较高时可选 P1、720p 或较低帧率。远程桌面、受保护内容及某些独占全屏应用可能无法采集。

分辨率、刷新率与码率

可选择 720p / 1080p，以及 60 / 75 / 90 / 100 fps。扩展屏刷新率跟随所选帧率，眼镜面板刷新率由设备决定。主屏始终保留原分辨率，采集画面等比缩放并补黑边。SDK 单帧预算限制对应最高码率为 24 / 30 / 32 / 40 Mbps；不能在 60 fps 强行选择 40 Mbps。

FPV 低延迟设置

默认目标为 1080p / 100 fps / 20 Mbps / NVIDIA P4。当前版本直接按目标帧率使用一个高精度采集时钟，不再从 240 Hz 轮询画面中筛选。编码前只保留一张等待画面；电脑过载时，新画面可替换尚未编码的旧画面，减少积压。因此不承诺过载时零丢帧。已经编码的 H.264 参考帧仍按顺序发送，编码后不增加节拍等待。

继续沿用 0.2.4 的采集调度：根据稳定的真实桌面更新时间微调后续采集时机，目标放在估计更新时刻之后约 3 ms，每次修正最多 ±100 微秒，以减少刚好错过更新的情况。重复画面和不可靠样本不参与估计。这不是新增编码缓冲，不会自动降低所设码率，也无法同步眼镜未公开的显示时钟。

电脑主屏和独立扩展屏共用同一流程。60 Hz 主屏不会因目标设为 100 fps 而产生 100 个不同画面，独立扩展屏可设为 100 Hz。游戏渲染和显示时序仍会影响实际延迟，不能仅凭相同代码保证两种来源物理延迟相等。

本版未重新测量显示器到镜片的光学延迟，不能宣称已达到原作者在特定硬件上的约 12 ms，也未证明全程延迟或码率波动不超过 1%。实时 USB 数字不包含前后图像处理和眼镜显示。

画面处理与调度

NVIDIA 显示输出在 GPU 上完成 SDR BT.709 色彩转换、等比缩放和补黑边。放大较小来源时，先放大 RGB 再转换为 NV12，避免同时处理时的边缘偏色；等尺寸或缩小仍只处理一次。混合显卡电脑若从其他厂商显卡采集，需要 CPU 中转，但编码始终使用 NVIDIA NVENC。

0.2.5 改用 H.264 High / CABAC，提高固定码率目标下的运动压缩效率，减少快速运动和细纹理的量化失真，并调整色度量化以改善颜色边缘；RGB 转换和缩放不变。编码始终使用 NVIDIA NVENC，保留 P1/P4、超低延迟模式、qres 码率控制、VBV 预算和单帧保护。仍然关闭 B 帧、前瞻和周期性帧内刷新，不增加输出缓冲。所设码率是压缩目标，不是每帧固定大小。

NVENC 通过完成事件读取已就绪码流，沿用 0.2.4 的 High（4）GPU 调度请求，并记录 Windows 是否接受；不修改模拟器或其他进程。客户端保留高于普通的 CPU 优先级并尽可能关闭自身编码进程的节能降速，不修改全局电源计划，也不使用 CPU 实时优先级。调度策略不保证所有负载下的延迟恒定。

实时统计与 USB 速度

统计每 100 ms 更新，发送帧率和带宽使用最近一秒的数据。带宽包含成功写入 USB 的视频及协议数据，不包含 USB 总线开销；静止画面可能显著低于所设码率。USB 发送耗时只测量一次视频写入，不包含采集、编码、调度等待和眼镜解码显示，不能当作端到端延迟。SDK 没有返回眼镜显示时间戳。

统计保留低开销计数，界面更新由独立线程处理；界面忙碌时合并旧统计，不阻塞视频发送。本版移除了串流进程内重复的设备枚举，独立 USB 插拔监听和故障后的设备确认仍保留。

本 SDK 的 MI04 通道使用 512 字节 Bulk 端点，对应 USB 2.0 High Speed（理论总线速率 480 Mbps）。更快的电脑接口不会把该通道升级成 USB 3.x；实际视频速率还受固件单帧预算和解码能力限制。Bulk 传输仍受主机调度、驱动与设备完成时机影响，有线连接不保证固定完成时间。

使用独立扩展屏（实验性）

选择「独立扩展屏」，首次点击「安装扩展屏驱动」并完成 Windows 管理员授权。升级旧版驱动配置时点击「更新扩展屏配置」。选择分辨率和帧率后开始串流，Windows 自动创建主屏右侧的独立桌面。用 Win + Shift + → 把模拟器移过去，也可在模拟器内部选择该显示器。

停止、拔线或退出客户端时自动收回扩展桌面，Windows 会重新安排其窗口；驱动保留以便下次使用。无需反复安装或手动启用、断开显示器。USB 仍使用原 SDK 协议，主屏无需改成 16∶9。

本版内置已签名的 MIT 开源 VDD 25.7.23，保留原驱动与签名，不导入证书或启用测试签名。如果 Windows 拒绝安装，请查看安装错误及上游说明，不要关闭驱动签名保护。检测到其他软件的 VDD 时不会覆盖配置。需要卸载时前往「桌面串流 → 独立扩展屏 → 移除扩展屏驱动」；此操作需要管理员授权，客户端卸载不会自动删除系统驱动。

客户端仅管理自身安装的唯一 VDD，不覆盖其他软件的显示配置。参考：VDD 源码及说明。
