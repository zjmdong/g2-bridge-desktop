### 清理错误的修复前证据

纯 mock 重放：worker 收到停止请求，随后串流函数抛出
`RuntimeError('virtual display cleanup failed')`。
0.3.0 实际返回 `exit_code=0`，没有输出任何 error 事件。
新增五项回归在修复前为三项失败、两项通过，确认问题不是仅凭推测提出。
测试没有调用真实 USB、显示配置、驱动或 GPU API。

## 最小上游改动的审查结论

“最小改动”应按需要改变的行为和维护边界判断，不能仅以新增行数少为目标。

- 保留作者的布局、控件、SDK 设置模型和 USB 协议；Windows 特有逻辑放在
  `goggles_bridge/app/windows/`，避免修改 macOS 的实际捕获实现。
- SDK 的 GPU priority 参数保留原 CLI 默认值；桌面适配器选择自己的优先级。
- 原生 FFmpeg patch、对应源码及构建说明是现有性能后端的实际依赖，不能通过删掉许可证、
  来源说明或必要回归测试来缩小 diff。
- fork 的版本号、更新渠道、发布工作流和安装包交付不应直接混入首个上游性能 PR。
  当前 Windows 打包需要经过 manifest 校验的 native 输入，这与上游直接下载 stock FFmpeg
  的流程不同；提交前应单独讨论该依赖，或先拆分可独立审查的功能 PR。
- 不建议把整个产品分支的所有提交一次性作为第一个 PR。先讨论虚拟屏/原生依赖范围，
  再按可独立验证的变更拆分；详见首次贡献演练文档。

## 验证状态

独立审查复核通过：

- `python -m unittest discover -s tests -p test_cleanup_failure.py -v`：5 项通过。
- `python -m unittest discover -s tests -p test_app_diagnostics.py -v`：1 项通过，包含
  物理 WGC、物理 DDA、虚拟屏三种子场景。
- 未使用遥测模块的引用搜索无产品代码残留；清理后保留了 USB 故障恢复所需的存在性查询。
- 复核了设置 schema 迁移：0.3.0 实际使用的 startup-only 策略迁移为 app-only 的
  `keyframe_seconds=0`；传给 SDK 时仍使用既有合法枚举；上游原设置不套用这一迁移。
- 复核了 Baseline/CAVLC 与 High/CABAC 的配对、预检/正式命令共享、WGC 不接收
  native-only 参数、实体屏偏好不被虚拟屏覆盖的代码路径。

本次独立审查已定位的配置、清理与诊断问题均已修正，未发现仍需阻止本轮交付的同范围问题。
完整测试、打包及硬件检查结果由主任务的交付说明汇总；本审查没有执行真实 USB、GPU、
显示模式或驱动操作，也没有测试 macOS 真机。仍需在实际游戏和眼镜上评估画质与端到端延迟，
不能把 mock 回归或源码审查等同于“全平台无 bug”。
