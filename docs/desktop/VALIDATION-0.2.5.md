# 0.2.5：运动画质与颜色边缘修正

交付记录：2026-11-12。本次针对用户报告的大幅运动时新增噪点、模糊，保持
Windows / NVIDIA NVENC / 1080p100 / 20 Mbps 目标。原测量文件保留各自记录时间。

## 归因与验证范围

0.2.3 与 0.2.4 的编码质量参数没有变化。同一段 500 帧生成画面通过两版原生二进制后，
全部 H.264 access unit 逐字相同。因此，本轮没有确认一个“0.2.4 更换编码器导致损坏”的回归。
此前的平色、灰阶和小范围运动检查不足以覆盖高速运动的压缩质量，现补充确定性运动纹理、
场景突变、逐帧真值和真实原始帧替换压力检查。

本轮确认了可以修正的客户端策略问题：早期兼容调试留下的强制 Baseline 限制了
同一目标码率下的运动压缩效率。上游使用并验证过 High；早期仅改 Baseline 的尝试也曾黑屏，
不能将当时多个兼容改动组合的成功全部归于 Baseline。
保留已验证的 NV12 转换和无色彩描述 VUI，改用 High/CABAC。

540 帧的 CPU NV12 与 GPU 上传转换对照，逐帧质量、身份、帧长和初始 QP 记录完全一致；
另一次 240 帧独立 GPU 转换/回读中，Y/U/V 三个平面逐像素匹配真值。
这些证据支持该生成样本的误差来自有损编码，没有发现 GPU 转换额外造成噪点。
它们不证明任意实际游戏、DDA 捕获或眼镜显示都没有其他问题。

## 最终修改

- H.264 High + 显式 CABAC，继续使用 NVIDIA NVENC。
- 对 Cb、Cr 分别设置 `-qp_cb_offset -4`、`-qp_cr_offset -4`，保护饱和颜色与黑边交界。
- 环境检测、采集检测、实际串流和诊断元数据共享编码策略。
- 保留 qres、P1/P4、ULL、固定目标码率、原 VBV 和 56,000 字节整帧保护。
- 保留无 B 帧、无 lookahead、单参考、启动 0/1/2 秒 IDR、无周期 IDR；没有新增编码后缓冲。
- 0.2.4 的源相位对齐、GPU High 调度、原始帧邮箱、颜色转换和 USB 协议均未修改。

原生 FFmpeg 二进制和补丁完全沿用 0.2.4；FFmpeg SHA256：
`bff0c6fe837a68f64f8f426fdd403de04e84e3211fe46875655bdf001ebf28fd`。
SDK 70 文件基线及原有两处精确审计补丁保持不变。

## 画质证据与取舍

所有候选使用同一生成序列、1080p100、20 Mbps 目标和 P4。
下表 PSNR 先聚合逐帧均方误差再换算，不是直接平均逐帧 dB。

| 场景 | 原 Baseline 的 Y-PSNR | 最终配置的 Y-PSNR | 亮度均方误差降低 |
| --- | ---: | ---: | ---: |
| 快速平移 | 37.75 dB | 40.49 dB | 46.75% |
| 场景突变 | 34.07 dB | 37.46 dB | 54.18% |
| 细纹理 | 30.31 dB | 31.57 dB | 25.08% |

最终 540 帧全部正确解码，八区身份一致，参考序号连续；从最后 IDR 重新解码与完整
参考链逐帧哈希一致。最大编码帧 42,742 字节，未触发整帧保护。
实际有效码率随内容与编码策略变化，所以这些是**相同目标码率**的结果，不能称为
严格相同编码字节量的收益，也不能将合成指标等同于用户实际游戏观感。

直接 High、色度偏置为 0 的中间候选在一个宽画幅红色边界出现 6 个码值误差，
超过原有 4 码值门槛。该位置的变换块同时覆盖红色与黑边，原始转换仍正确。
对称 -4 偏置使六组几何/颜色检查通过，**没有放宽测试阈值**。
相对 High-only，最终方案将部分固定预算分给色度：亮度 PSNR 有约 0.03–0.44 dB
的小幅取舍，但仍明显优于原 Baseline。历史候选和失败结果均保留。

没有采用 fullres：它在持续平移、细纹理中平均得分更好，但突变最坏亮度 MSE
约 85.64，明显差于 High/qres 的 22.39；最终色度偏置方案约 24.02。
空间 AQ 8 的收益较小，局部坏块和突变误差增加，也没有采用。
没有通过增大 VBV、提高码率、恢复周期刷新或软件编码掩盖误差。

## 回归检查

- 六组几何的颜色、灰阶、黑边、纹理复用和帧序检查通过；保持原始分量误差 2、
  编码分量误差 4 的门槛，GPU 与 CPU 参考编码路径各 288 帧。
- 720p/1080p × 60/75/90/100 fps × P1/P4，分别验证 8 Mbps 与各档支持的最大码率，
  共 32 组、7,960 帧全部解码成功，无超限帧；20 Mbps 目标另由运动质量序列验证。
- 17 区帧号/CRC 压力检查保留真实 GPU 转换、latest mailbox 和异步 NVENC，
  刻意通过慢读造成背压，要求真实原始帧替换，允许编码前跳号但禁止混帧和参考链丢失。
  此压力测试不是正常延迟或零丢帧证明。

- 最终压力配置：1,000 个输入中 828 个在编码前被最新帧替换，172 个完整解码；
  17 区身份/CRC、最终帧排空和参考链检查均通过。没有把压力下的主动替换当作正常流畅度成绩。
- 实时扩展屏合成纹理源采用 1080p/100 Hz，串流 100 fps/20 Mbps/P4。
  旧配置采样 20 秒、新配置采样 30 秒，各排除前三秒启动期。新配置的 2,700 个测量帧
  平均 99.991 fps，主机 AU 输出间隔中位数 9.9965 ms、P99 11.8253 ms、最大 13.0625 ms；
  旧配置为 9.9909/11.4597/12.3263 ms。两者均没有超过 15 ms 的间隔、超限帧或
  latest mailbox 原始帧替换。新配置分包耗时中位数 0.3399 ms、P99 0.5632 ms。
  这是短时串行对照，不能证明时序完全等价或 ±1% 稳定，也没有测量采集到镜片的延迟。
  新配置 P99 比旧配置略大，当前证据只支持没有新增明显停顿或帧积压。
  测试窗口关闭后已恢复仅原主屏活动，原主屏保持 3440×1440/100 Hz。

主机回归的数值与原始报告哈希见 [发布检查摘要](evidence/v0.2.5-release-validation.json)。
本轮最后验证时未检测到眼镜 USB，未进行新的镜片显示或光学延迟验收。
