# DJI Goggles Streamer 0.2.2

## 安装与使用

1. 运行 `DJI-Goggles-Streamer-0.2.2-Setup.exe`，为当前用户安装或升级，保留设置。
2. 在「设备与驱动」确认 H.264 编码测试通过，连接已开机的眼镜。
3. 缺少 USB 驱动时点击「下载并安装驱动」，或导入 DJI Assistant 2 消费机系列
   2.1.42 离线安装包。首次官网下载约 354 MiB；客户端校验后提取驱动，管理员
   授权由用户在 Windows 中完成。不捆绑 DJI 固件或未经许可的 DJI 安装程序。
4. 在眼镜中进入「更多 → DJI Virtual Flight」。默认开启 USB 插入自动串流，
   也可关闭该选项后手动开始。手动停止后，下次重新插线才再次自动开始。
5. 停止、拔线或退出客户端时释放编码、USB 和串流扩展屏。

需要 Windows 10 2004 / Windows 11 x64、支持 Desktop Duplication 的显示驱动
和数据线，以及支持 H.264 NVENC 的 NVIDIA 显卡和驱动。0.2.2 仅使用 NVIDIA
硬件编码，不提供软件编码或软件回退。NVENC 初始化失败时会提示修复驱动，
不会通过 CPU 编码继续串流。P1 为速度优先，P4 为画质优先；实际游戏负载和
显示刷新节奏仍会影响流畅度。桌面采集与色彩转换仍有 CPU 工作。

SDK 已测试固件：Goggles 2 01.11.00.00 / 01.14.00.00、Integra 01.09.00.00。
本客户端的光学验收设备为 Goggles 2 01.14.0000。01.12 有上游黑屏报告，未知
版本会阻止串流。客户端提供官方更新/恢复教程，不自动刷机；可升级或降级的
版本以 DJI 官方工具实际列表为准。

## 画面参数

可选择电脑主屏或独立扩展屏；特定窗口选择和 macOS GUI 尚未实现。
两档分辨率：1280×720 / 1920×1080。扩展屏刷新率跟随目标帧率，眼镜面板
实际刷新率仍由设备决定。主屏等比缩放并补黑边，保留带鱼屏原有分辨率、
刷新率与主屏状态。Desktop Duplication 不显示 WGC 的黄色采集边框。
FPV 的默认目标为 1080p / 100 fps / 20 Mbps / NVIDIA P4。电脑主屏与独立扩展屏
共用同一采集和发送策略。60 Hz 主屏每秒最多产生 60 个不同画面，目标 100 fps
不会将其变成 100 Hz；扩展屏可按 100 Hz 创建。游戏自身的帧率和呈现队列仍需
跟上目标刷新率，客户端不会修改主屏或模拟器的设置。

| 帧率 / 扩展屏刷新率 | 最高码率 |
| --- | --- |
| 60 fps / Hz | 24 Mbps |
| 75 fps / Hz | 30 Mbps |
| 90 fps / Hz | 32 Mbps |
| 100 fps / Hz | 40 Mbps |

全部码率在界面中可见，超出当前 SDK 预算的选项标明最低帧率并禁用。
SDK 的 50,000 字节平均帧预算和 56,000 字节单帧保护保留。
设定码率是编码目标，静止画面的实际传输量通常较低。

## 独立扩展屏

首次选择此来源并安装内置签名 VDD 25.7.23 驱动。从旧版升级时点击「更新
扩展屏配置」，完成管理员授权，启用两种分辨率与四档刷新率。
开始串流时自动创建主屏右侧的 Windows 桌面，用 Win + Shift + → 移动模拟器，
或在模拟器内部选择该显示器。停止或拔线自动收回桌面，Windows 重新安排窗口；
驱动保留以供下次使用，无需反复安装或手动启用、断开。

此功能由虚拟显示驱动提供独立桌面，再由 SDK 经 USB 发送给眼镜，不是把眼镜
USB 改造成物理 DisplayPort。客户端只管理自身安装的唯一 VDD，不覆盖其他
软件配置；多个同类虚拟显示器会拒绝自动选择。驱动保留原签名，不导入证书
或关闭签名验证。「移除扩展屏驱动」需要管理员授权，卸载应用不自动删除系统
驱动。参考：[VDD 官方说明](https://github.com/VirtualDrivers/Virtual-Display-Driver/tree/25.7.23)。

## 图像和流畅度

显式限幅 NV12 转换、Baseline、无 B 帧、NVIDIA NVENC 超低延迟编码。
关闭编码前瞻，保留 SDK 的四分之一分辨率双遍码率控制和单帧保护限制。
0、1、2 秒提供关键帧建立解码画面，随后取消会引起周期闪烁的强制 IDR。
仅发送第一个关键帧在验收设备上会黑屏，因此保留启动阶段的重复关键帧。
传输失败或超大帧后，SDK 重启编码并重新执行启动阶段。

0.2.2 删除了发送端节拍等待。之前的等待会在短暂停顿后阻止积压帧及时排空，
让画面越来越旧。现在只在编码之前选择原始帧，编码好的参考帧立即按顺序发送，
不会通过丢弃任意 H.264 帧破坏解码。采集中断后不补播旧图追赶时间轴。
采集源直接进入处理滤镜图，避免 lavfi 输入和解码队列在选帧前保留旧纹理。
会话日志在独立线程异步写入；关闭 FFmpeg 周期进度输出，避免发送线程等磁盘。
两种来源不再有不同的应用等待策略，但物理屏、虚拟屏和游戏呈现时序仍不同，
无法仅凭源码保证输入到眼镜的物理延迟完全相等。
此前 NVENC 在眼镜端曾出现灰阶局部偏色；0.2.1 当前配置的用户验收未发现偏色，
但不代表所有内容均已验证。本版不使用软件编码绕过问题。
受保护内容不能采集，部分独占全屏或远程桌面需要改用窗口或无边框全屏。

## 实时统计和 USB

每次成功发送时记录计数与 USB 写入耗时，独立线程约每 100 ms 更新界面。
带宽、帧率使用最近一秒窗口。统计不在视频线程排序、绘图或写 IPC；界面卡住
时只保留最新统计，不能反向阻塞视频发送。

USB 发送耗时不包含采集、编码、调度等待或眼镜显示。SDK 不返回眼镜显示
时间戳，无法由这些计数得到实时端到端延迟。带宽包含成功写入的协议和视频
字节，不包含 USB 总线开销。

原作者约 12.1 ms 为特定硬件、固件、240 Hz 参考显示器及原生 D3D11 路径的
显示器到镜片附加延迟，不是模拟器输入到眼镜的总延迟。0.2.2 按源码消除了
确定的额外等待和积压，并通过自动化验证；未重新进行光学延迟测量，不能将
界面中的 USB 耗时或稳定帧率当作已经达到 12 ms 的证明。

SDK 的 MI04 通道为 512 字节 Bulk 端点，对应 USB 2.0 High Speed，理论总线
速率 480 Mbps。更快的电脑接口不会将此通道升级为 USB 3.x；视频速率还受
固件单帧预算与解码能力限制。客户端拒绝速度不足的 Full Speed 连接。

## 诊断与开发

安装包尚无商业代码签名，发行 SHA-256 用于核对文件。DJI 驱动保留原厂签名。
设置、缓存和日志位于 `%LOCALAPPDATA%\DJI Goggles Streamer`；诊断导出不包含
桌面截图或完整 USB 原始数据，不自动上传。卸载保留用户数据和共用驱动。

SDK 文件保持不变，应用在 `desktop_app/`，测试在 `desktop_tests/`。
`python packaging/windows/verify_sdk.py` 检查基线。Python 3.11 x64 安装
`requirements-build.txt` 后执行 `python packaging/windows/prepare.py`，
再运行 `python -m desktop_app`。使用 `packaging/windows/build.ps1` 打包，
`-Iscc` 可指定 Inno Setup 编译器。

功能更新递增次版本，修复/测试递增补丁版本。提交格式为
`type(scope): lowercase imperative description`，文档使用 `chore(docs)`。
在用户 fork 的分支开发，保留原 CLI，便于后续回馈上游。
