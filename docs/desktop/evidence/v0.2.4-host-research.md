# 0.2.4 host timing evidence

The selected policy uses NVIDIA GPU scheduling class **HIGH (4)** and follows
the observed desktop update phase with a **3 ms acquisition margin**. Research
used generated moving content at 1920×1080, 100 Hz, NVENC P4 and a 20 Mbps target.
The frozen 0.2.3 command and reproducible diagnostic sources are in
[`packaging/windows/frame_age`](../../../packaging/windows/frame_age/README.md).

[`v0.2.4-host-research.json`](v0.2.4-host-research.json) preserves all 38 completed
research cases, including rejected candidates, with source/binary hashes and
numeric source correlations. Each table row below is a 60-second run with the
first 3 seconds excluded, on the same continuously running texture generator.

| Research policy | Output frames | Repeated desktop images | Raw mailbox replacements | Output interval p99 / max | Desktop update → host arrival p99 / max |
| --- | ---: | ---: | ---: | ---: | ---: |
| Original REALTIME (5), free-running capture | 5,670 | 48 | 30 | 16.65 / 47.16 ms | 22.74 / 45.81 ms |
| HIGH (4), source phase + 3 ms | 5,700 | 0 | 0 | 11.81 / 12.72 ms | 11.57 / 12.50 ms |

The latest-frame mailbox prevented an encode stall from becoming a growing
queue. The tests identified GPU scheduling priority as a cause of the stalls;
phase alignment separately reduced sampling near the desktop update boundary.
Holding the DDA frame until the next nonblocking acquire instead produced
alternating timeouts and approximately 50 distinct images per second, and was
rejected. MMCSS and video-processor variants were not selected.

The first phase estimator could fail to acquire lock after repeated missed
samples. Its replacement accepts a two-period gap only when DXGI also reports
two accumulated desktop updates; a real 50 Hz source remains distinguishable.
Four 30-second tests of the revised 2/3 ms margins each observed 2,700 distinct
images without replacements. A longer 90-second 2 ms run had 43 repeated images;
39 source gaps overlapped gaps in the generator's own presentation. The final
3 ms policy retains extra acquisition margin. These are observed windows, not
a guarantee of zero loss for every application or GPU workload.

The final marker test decoded all 608 generated frame IDs and QPC timestamps
and matched them exactly to the renderer log. Its bounded measurement window
contained 400 distinct consecutive images. Render submission → host arrival
was 19.67 ms median and 21.74 ms p99, including 11.56 ms median before the OS
desktop update timestamp. This is a host measurement, not goggles optical
latency; it cannot establish the original author's reported 12 ms result.

[`v0.2.4-release-validation.json`](v0.2.4-release-validation.json) records separate
tests of the actual uninstrumented release binary and the unchanged USB writer:

| Release USB test | Mean completion rate | Completion interval p99 / max | USB write call p99 / max | Failed writes |
| --- | ---: | ---: | ---: | ---: |
| Extended generated texture, 60 s | 99.9964 fps | 12.07 / 13.13 ms | 0.98 / 2.95 ms | 0 |
| Primary 3440×1440 desktop scaled to 1080p, 20 s | 100.0033 fps | 12.25 / 13.05 ms | 0.36 / 0.54 ms | 0 |

Every full steady-state one-second USB bin contained 100 frames. The moving
texture's estimated encoded rate averaged 19.5286 Mbps, ranging from 19.4213 to
19.6283 Mbps across 57 bins: at most 0.55% from the observed mean. This does **not**
meet ±1% of the configured 20 Mbps target. The mostly static primary desktop
used fewer coded bits and is not a comparable image-quality test.

Individual frame intervals also **do not meet ±1%**. USB bulk completion on the
host cannot demonstrate wire packet timing, goggles decoder timing, panel
scanout or constant end-to-end latency. Rate, age, repeats and source cadence
are reported separately; nominal PTS and average FPS cannot prove freshness.

Release checks also passed generated pixel/frame-order comparisons and all
16 codec modes (3,980 encoded and decoded frames). The release contains none of
the diagnostic metadata, timestamp arrays or offline marker decoding. Public
files contain numeric summaries only, with no desktop images, raw counters,
device identities, handles or private paths.
