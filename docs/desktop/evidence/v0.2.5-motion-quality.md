# 0.2.5 运动画质对照

画质检查最终选择 **NVIDIA H.264 High/CABAC、qres、Cb/Cr 量化偏置均为 -4，不启用 AQ**。
这项偏置调整量化精度，不是给像素色值减 4。首轮无偏置 High 是中间候选；
其后颜色边缘检查失败、新偏置候选的独立验证与亮度/色度取舍均保留在下文。
正式串流时序、完整档位和安装验收由发行主报告另行记录。
参数仍为 1920×1080 / 100 fps / 20 Mbps / P4，保留 400,000 bit VBV、
无 B 帧、无 lookahead、原始帧最新槽和启动关键帧策略。
这些是生成视频的主机画质检查，不是眼镜光学验收或实时延迟测量。

## 对照与结果

首轮五个候选使用同一版本 FFmpeg、同一冻结命令模板、同一确定性生成源和种子。
后续色度候选使用同一生成工具、内容与种子，并以含显式 CABAC 和 -4 偏置的独立模板记录来源哈希。
540 帧包含 300 帧慢移、各 60 帧快速平移、场景突变、细纹理及每帧重新生成内容的压力段。
每帧均通过相同的 RGB 上传、D3D11 转换和 NVENC 路径；它不包含 DDA 桌面捕获。

下表 PSNR 由逐帧像素 MSE 的平均值再换算得到，**不是逐帧 dB 的算术平均值**。
码率是去除 filler 后编码 AU 字节按名义 100 fps 换算的有效码率。
虽然目标均为 20 Mbps，实际有效码率不同，不能把结果称为严格等实际码率的比较。

| 候选 | 快速平移 Y-PSNR | 突变 Y-PSNR | 细纹理 Y-PSNR | 突变最坏帧 Y-MSE | 全序列有效码率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Baseline / qres | 37.75 dB | 34.07 dB | 30.31 dB | 49.74 | 8.36 Mbps |
| High / qres，无色度偏置（中间候选） | 40.92 dB | 37.69 dB | 31.60 dB | 22.39 | 8.81 Mbps |
| Main / qres | 41.29 dB | 38.09 dB | 31.35 dB | 21.30 | 8.05 Mbps |
| High / fullres | 43.56 dB | 35.68 dB | 33.02 dB | 85.64 | 17.77 Mbps |
| High / qres + spatial AQ 8 | 40.94 dB | 37.47 dB | 32.00 dB | 24.08 | 9.13 Mbps |
| **High / qres + 色度偏置 -4（选用）** | **40.48 dB** | **37.46 dB** | **31.57 dB** | **24.02** | **9.41 Mbps** |

无偏置 High/qres 相较 Baseline/qres 的快速平移、突变、细纹理亮度 MSE 分别减少约
51.84%、56.57%、25.60%。排除每帧新内容压力段后的 480 帧，MSE 减少约 38.62%。
High 的 PPS 确认启用 CABAC 和 8×8 变换；原有无色彩描述 VUI 和无重排序策略保留。
这证明该样本存在可改善的压缩失真，不证明用户眼镜中所有异常均由同一个原因引起。

Main/qres 在快速平移和突变上略好，细纹理上略差，没有形成统一优势。
High 与上游已使用的配置一致；这里没有为单一合成源引入新的 Main 策略。

## 为什么没有选择更高的平均分数

fullres 在慢移、快速平移和细纹理上显著提高平均保真度，并使用更多有效码率，
但突变段发生更大的瞬时误差。第 384、396、408 帧的 Y-MSE 约为 83–86，
High/qres 同段最坏约 22。突变段 MSE 大于 100 的 16×16 块比例从 0.00518% 增至 1.79934%。
它不适合仅凭总体平均画质分数作为此次大幅变化噪点的默认修复。

AQ 8 的快速平移收益仅约 0.02 dB；细纹理平均误差改善，但坏块比例从 5.983% 增至 6.408%，
突变平均和最坏误差也略增。未将其默认开启。
这些块误差阈值是诊断量，不是已经校准的视觉感知阈值。

qres 的首遍分析分辨率较低，fullres 的统计更细，但两者最终都输出 1080p。
观察到的差异与首遍分析和比特分配变化一致；驱动内部决策未被测量，不能据此认定 NVIDIA 缺陷。
初始 slice QP 也不等于每个宏块的实际 QP，尤其不能用它直接判断 AQ 后的局部质量。

## 完整性与版本边界

六个候选均完整解码 540 帧，八区身份全部正确；从最后一个启动 IDR 单独重新解码的
340 帧与连续解码逐帧哈希一致。没有参考帧序号异常，没有超过 SDK 56,000 字节保护值。
最大 AU 从 42,742 到 44,204 字节。该保护值不是已逆向确认的接收器缓冲大小。

对 0.2.3 与 0.2.4 原生二进制进行另一个同输入、同 Baseline 参数的 500 帧对照，
500 个编码 AU 全部逐字一致。这排除了该生成样本中原生编码逻辑的新差异，
不能排除捕获源、实际负载或接收显示路径的变化。

另外对无色度偏置 High/qres 中间配置，将相同生成源直接作为 CPU 内存 NV12 输入交给 NVIDIA NVENC，
与 GPU 上传/转换路径相比，
540 帧的所有误差指标、身份、AU 大小和初始 slice QP 记录完全相同。
该对照没有保存跨路径的完整编码或解码字节哈希，因此不把相同指标写成逐字相同的输出。

独立的 240 帧 GPU 上传、转换、读回检查中，Y、U、V 三个平面的逐像素最大误差均为零，
身份全部正确。这进一步支持该生成样本的失真主要位于共同编码路径。
它是单独的一轮生成内容检查，不是实际 NVENC 输入 surface 的逐张读回，也没有覆盖真实 DDA。

独立 mailbox 压力测试使用 17 区帧号与 CRC，并通过故意慢读输出触发真实原始帧替换。
该测试验证纹理复用与参考链；统计不应当作正常串流丢帧或延迟表现。
三次均提交 1,000 张生成图：原配置完成 145 张解码，855 张在编码前被最新图替换；
无色度偏置的 High/CABAC/qres 中间配置完成 161 张解码，839 张在编码前被替换。
最终 Cb/Cr 偏置 -4 配置另行完成 172 张解码，828 张在编码前被替换，最小标记间距 78.5。
最终结果的 PPS 再次确认 High/CABAC、两个 -4 偏置及无重排序，独立模板与原始报告哈希单独记录。
输入与输出差额分别与原生 mailbox 替换计数一致；三次均无混帧、无不确定标记、无重复/倒序和参考链异常。
这些是刻意施加背压的覆盖结果，不能解释为正常使用会丢这些帧。
标记覆盖和有限样本通过并不能证明任意画面、任意负载均无纹理问题。

[数值与来源哈希](v0.2.5-motion-quality.json)保留所有候选及被拒方案；
[独立复现工具](../../../packaging/windows/motion_quality/README.md)不导入客户端运行路径。
公开记录不包含桌面图像、设备身份、原始 USB 内容或用户目录。

## 后续颜色边缘回归：保留失败，不放宽门槛

无色度 QP 偏置的 High/qres 在原有生成颜色检查中失败：344×144 等比放大并填充至
1280×720，内容区域为 `[0, 92, 1280, 534]`；第 8 帧纯红图的第 23 个样点位于
内容最后一行、紧邻下方黑边。期望 Y/U/V 为 63/102/240，解码值为 66/107/234，
最大误差 6 超过原有门槛 4。原始转换检查通过，前两组无边框几何也通过。
这更符合该高对比边界的编码误差，不能据此推断全屏颜色矩阵错误。

对称 `qp_cb_offset=-4`、`qp_cr_offset=-4` 候选保留相同目标码率、VBV、qres 和无重排序策略。
它通过全部六组几何检查；raw 与 decoded 门槛仍为 2 和 4，没有修改。
原失败几何的最大组件误差降至 3；全部六组灰阶色度误差为零。
负色度偏置会改变固定预算中的亮度/色度分配，因此又单独运行了相同 540 帧运动序列。
新候选完整性全部通过、最大 AU 42,742 字节，PPS 的两个色度偏置均确认为 -4。
相较原 Baseline，快速平移、突变、细纹理亮度 MSE 仍分别减少约 46.75%、54.18%、25.08%。

这个取舍并非所有指标都更好。相较无偏置 High，三段亮度 PSNR 分别下降约
0.436、0.233、0.031 dB，而合并 U/V 的色度 MSE 分别减少约 46.20%、33.78%、31.98%。
三段聚合 YUV-PSNR 的变化为 +0.049、-0.075、+0.071 dB。
突变最坏亮度 MSE 从 22.39 增至 24.02，仍低于 Baseline 的 49.74；没有出现 fullres 的 85.64 尖峰。
本次选择这项有限的亮度精度取舍，以满足未放宽的颜色边缘门槛；原始失败和全部中间结果均未替换。
